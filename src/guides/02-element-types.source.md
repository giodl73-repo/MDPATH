# md:// Element Types and Kinds

Every element in a markdown document has a type. mdpath uses the type to find
the right elements within a section, to classify what a fenced block contains,
and to determine which sub-selectors are valid. You specify the type in a URI
with the `:type:` component — and you can narrow it with an optional `.kind`
qualifier when there are multiple subtypes in the same section.

mdpath recognizes ten element types — six structural markdown primitives plus
four generic document concepts added for generated content. All are addressed
the same way in URIs: `:type.kind:selector`.

## figure

A figure is any ASCII art diagram inside a fenced code block. mdpath
detects figures by scanning for box-drawing characters (`┌`, `│`, `└`, `─`, `╔`, etc.)
or significant whitespace structure.

```
figure (kind=flowchart)

┌─────────────┐
│   Request   │
└──────┬──────┘
       │
       ▼
┌─────────────┐
│   Handler   │
└─────────────┘
```

### Figure label matching

The figure's label comes from the first text-only line inside the fence:

````
```
my-diagram-label         ← this becomes the label

┌────────────────┐
│  box content   │
└────────────────┘
```
````

Address it: `:figure:my-diagram-label`

### Figure kinds

| Kind | Detection | Example URI |
|------|-----------|-------------|
| `flowchart` | Arrow connectors + boxes | `:figure.flowchart:request-flow` |
| `box` | Rectangular box structure | `:figure.box:architecture` |
| `sequence` | Vertical sequence with `─►` arrows | `:figure.sequence:login-flow` |
| `timeline` | Horizontal timeline markers | `:figure.timeline:release-history` |
| `graph` | Nodes connected by lines | `:figure.graph:dependency-graph` |

## table

A table is a markdown pipe table. mdpath auto-detects the kind from structure.

| Kind | Detection | Example |
|------|-----------|---------|
| `key-value` | 2 columns, col 1 = key, col 2 = value | Config reference tables |
| `schema` | Has a "Type" or "Required" column | API docs |
| `comparison` | Parallel columns comparing options | Feature matrix |
| `data` | General multi-column data | Benchmark results |

### Table addressing

```
:table:0                     ← first table
:table:metrics               ← table labeled "metrics"
:table:0[row=Goroutine]      ← specific row
:table:0[col=Stack Size]     ← specific column
:table:0[row=Goroutine,col=Stack Size]  ← specific cell
```

## chart

An ASCII chart is a fenced code block whose content uses bar characters (█▓▒░)
or plotted points to show data visually. Charts are distinguished from figures
by the presence of these specific characters rather than box-drawing structure.
Use the `chart` type in URIs when you need to address a bar chart or line plot
specifically, rather than letting it resolve as a generic figure.

| Kind | Detection |
|------|-----------|
| `bar` | Horizontal bars with labels and characters (▓, █, ░) |
| `line` | ASCII line plot with axes |
| `stacked` | Stacked bar patterns |

---

## text

The `text` type covers everything that isn't a figure, table, or chart: prose
paragraphs, bulleted lists, and generic code blocks. It's the catch-all for
unstructured content. Use `:text:0` to address the first paragraph in a section,
or `:text.code:0` for the first code block that isn't recognized as a figure.
In practice, you'll rarely address text elements directly — they're most useful
for extracting specific prose passages into other documents.

| Kind | Detection |
|------|-----------|
| `prose` | Plain paragraph text |
| `list` | Bulleted or numbered list |
| `code` | Fenced code block without figure structure |

## math

A math expression — LaTeX source or rendered ASCII art output.

Detected by fence_info (`math`, `latex`, `tex`) or by a `Classifier` extension.
proof's `ProofClassifier` maps `proof:math` fence_info to this type, so compiled
math blocks in generated docs are correctly addressable.

```
md://docs/math-guide.md:math:0            ← first math block
md://docs/math-guide.md:math:pythagorean  ← named math block
```

---

## tree

A tree or hierarchy diagram — org chart, taxonomy, dependency graph, dirtree output.

Detected by fence_info (`tree`, `org`, `taxonomy`, `dirtree`) or by `└──`/`├──`
branch patterns in content. proof's `ProofClassifier` maps all compiled tree
output kinds to this type.

```
md://docs/trees-guide.md:tree:0           ← first tree
md://docs/trees-guide.md:tree:org         ← org chart tree
```

---

## slide

A slide or presentation block generated by `proof:slide`.

Detected by fence_info containing `slide`. Each compiled slide in a `.slides.md`
output file is addressable as a separate `slide` element.

```
md://docs/slides.md:slide:0               ← first slide
md://docs/slides.md:slide:introduction   ← slide titled "introduction"
```

---

## dashboard

A dashboard canvas block generated by `proof:region` in a `.dashboard.md` file.

```
md://docs/status.dashboard.md:dashboard:header   ← named region
md://docs/status.dashboard.md:dashboard:0        ← first region
```

---

## heading

A single heading line:

```
:heading:the-big-picture    ← selects the "## The Big Picture" heading line
```

Useful when you want to reference the heading itself, not the section below it.

---

## section

A section is a heading plus all its content until the next same-level heading.
Sections are addressed via the `#heading-path` component, not the `:type:` component:

```
md://doc.md#the-big-picture              ← section
md://doc.md#the-big-picture:figure:0    ← figure inside the section
```

## Type auto-detection

```proof:tree kind=taxonomy
root: Auto-detection algorithm (DefaultClassifier + ChainClassifier)
- Caller's Classifier (if resolve_with_classifier used)
  - fence_info match → return type immediately
  - No match → fall through
- DefaultClassifier fence_info check (first)
  - math / latex / tex → Math
  - mermaid → Figure.flowchart
  - plantuml → Figure.sequence
  - dot / graphviz → Figure.graph
- DefaultClassifier content heuristics (second)
  - Bar chars (█▓) → Chart.bar
  - Tree branches (└── without ┘) → Tree.ascii
  - Box-drawing (┌╔) → Figure
    - Has arrow connectors? → flowchart
    - Rectangular box only? → box
  - Otherwise → unclassified (Text)
- Input pipe table
  - 2 columns, key/value? → table.key-value
  - Has Type/Required col? → table.schema
  - Multi-column data? → table.data
- Input heading line → heading
- Input prose paragraph → text.prose
```
